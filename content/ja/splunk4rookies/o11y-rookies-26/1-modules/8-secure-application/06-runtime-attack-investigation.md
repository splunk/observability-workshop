## ランタイム攻撃が議論を変える理由

定期スキャンは、ある時点で何が*問題になりうるか*しか教えてくれません。

Splunkのランタイム攻撃検出は、リアルタイムで何が*今起きているか*を教えてくれます —
既知の脆弱性に対するエクスプロイトの試行を、フォレンジックコンテキストとともに提供します。これにより、既にカタログ化された脆弱性と相関付けられた攻撃テレメトリを使って即時の調査と緩和が可能になり、SOCスタイルの調査をObservability Cloud内で完結させます。

### 攻撃データへのアクセス

> *「定期スキャンからランタイム対応の脅威検出へシフトします。」*

{{% notice title="Exercise" style="green" icon="running" %}}

1. **APM → Application Security** から **Attacks** タブを選択します。
![apm](../images/06-attack-nav.png)

2. 攻撃リストを確認します。各行について以下を確認してください
    - **Attack type** - エクスプロイト試行の分類
    - **CVE Reached** - 関係するCVEの脆弱性の数
    - **Environment & Service** - スタック内のどのエンティティが影響を受けているか
![apm](../images/06-attack-view.png)
{{% /notice %}}

### 攻撃の詳細を調査する

攻撃の完全なコンテキストを把握することで、緩和と修正のアクションを実行できます。どのような攻撃がアクティブか、どこで発生しているか、攻撃者がどのようなアクションを実行したか、脆弱なエントリポイントがどこかを把握することが重要です。

{{% notice title="Exercise" style="green" icon="running" %}}

1. 1つの攻撃アクティビティを選択して詳細ビューを開きます。
![apm](../images/06-attack-select.png)

2. フォレンジックフィールドを確認します
    - 攻撃された**サービス**、**環境**、および **CVE**
    - **イベントのシーケンス**と実行されたアクション
    - 具体的な**イベント**と**トリガー**
    - **Vulnerable Method** コード内のこの脆弱性リスクが存在する箇所
![apm](../images/06-attack-details.png)
{{% /notice %}}

{{% notice title="Note" style="info" %}}
    - これは確認可能なコンテキストの一部に過ぎません。この詳細ビューに表示されるすべての詳細を確認する時間を取ってください。
    - 他のAttack Typeをクリックして、それぞれで利用可能なコンテキストを確認してください。攻撃の種類によって、詳細が異なる場合があります。
{{% /notice %}}

### コードレベルのフォレンジック
>
> *「このエクスプロイト中にアクセスされたコードの正確な行を特定することで、アラートから修正までのループを短縮します。」*

{{% notice title="Exercise" style="green" icon="running" %}}

1. 攻撃詳細の下部にある **Stack Trace** 属性までスクロールします。

![apm](../images/06-attack-forensics-sel.png)

2. スタックトレースを展開します。
3. エクスプロイト中にアクセスされたコードのフレームと行参照を特定します。
![apm](../images/06-attack-forensics.png)
{{% /notice %}}

### 学んだこと

- Attacks タブがカタログ化された CVE に相関するエクスプロイトアクティビティをどのように表示するか。
- 攻撃の詳細が Observability 内で SOC 対応のフォレンジックコンテキストをどのように提供するか。
- スタックトレースがセキュリティアラートと開発者向けの修正をどのように橋渡しするか。
