In this section, use the [**Filter Processor**](https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/processor/filterprocessor/README.md)
to selectively drop spans based on OpenTelemetry Transformation Language
(OTTL) conditions.

Health checks are necessary, but their spans can be frequent and noisy. You
will remove spans named `/_healthz` before they reach the Agent's local or cloud
exporters while preserving the useful `/movie-validator` spans generated by
the same load test.

Before filtering, a health span looks similar to:

```text
InstrumentationScope healthz 1.0.0
Span #0
    Name           : /_healthz
    Kind           : Server
    Status code    : Ok
    Status message : Success
```

At scale, these spans add noise and consume processing, network, and storage
capacity without helping most investigations. The goal is to drop only the
known health-check operation while preserving application spans.

Continue in Config Builder with the `agent_config.yaml` imported in Step 1.5.

The filter runs before the Agent's exporters. The local `debug` and
`file/traces` outputs therefore show the same filtered spans prepared for the
backend.
